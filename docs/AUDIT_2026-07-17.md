# Audit of pre-existing prototype — 2026-07-17

This repository was found containing a previous agent's one-pass build whose status
documents overstated completion. This audit records the verified state at the git
baseline commit, before staged rebuilding began.

| Claim (docs as found) | Verified reality |
|---|---|
| `IMPLEMENTATION_STATUS.md`: ~19 outcomes `implemented` | 23 source files, 2,564 lines total for a 10-workspace app — prototype depth only |
| Same file: Phase 1 `in progress`, Phases 2–7 `not started` | Internally contradicts the outcome claims above |
| `COVERAGE.md` maps outcomes | Uses outcome codes (7.3.5, 7.5.2, 7.5.3) that do not exist in `YEAR_10_WAVES_MOTION_APP_PLAN.md`; exact syllabus wording never extracted from the curriculum source |
| Test suite | 8 unit tests, 1 failing (`units.test.ts` exact float equality on `500e-9`); `tests/e2e/` empty despite Playwright installed |
| `README.md` | Untouched Vite template boilerplate |
| Version control | No git repository until this audit |
| Component quality (sampled `WaveMeasurementLab.tsx`) | Real Canvas render + `v = fλ` + trial table, but: "Sound (Water)" preset sets 1500 m/s on a slider capped at 1000 (broken control); no keyboard access to measurement; no unit conversion UI; no Orient→Connect learning rhythm; no assessment; no reduced-motion support; no fallbacks |

## Disposition

- The existing code is retained as **prototype/scaffold only**. Tooling configuration
  (Vite, TypeScript strict, Vitest, Playwright, PWA plugin, oxlint) matches the shared
  specification's recommended stack and is kept.
- Every simulation component is treated as unverified prototype code, to be replaced or
  brought up to specification stage by stage. Nothing in the found state counts toward
  outcome coverage until it passes the stage gates in
  `docs/plans/2026-07-17-wavemotion-orchestration-plan.md`.
- `IMPLEMENTATION_STATUS.md` and `COVERAGE.md` are reset to honest values.
